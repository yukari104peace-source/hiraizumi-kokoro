# 画面設計：平泉の細道

作成日：2026-10-12

## 1. 設計の前提

`requirements.md` と、その後の会話で決まった内容を反映する。AIは使わず、70種類の言葉から2件を抽選する。写真一覧・登録・ログイン・投稿・編集の5画面とし、抽選や確認ダイアログのために画面を増やさない。

要件定義作成後に確定した追加仕様：

- パソコン・スマホとも写真一覧は1列。1ページ10件。
- 未ログインで投稿へ進んだ場合、先にユーザー登録画面を表示する。登録済みの人はログインへ進み、ログイン後は投稿画面へ戻る。
- 出典リンクは確認後に別タブで開く。
- 下書きは手動保存、1人1件、本人だけが再開できる。
- 未保存の変更があるまま離れる場合は確認する。

これらは本書と `routes.md` に記録する。今回 `requirements.md` 自体は変更しない。

## 2. 画面一覧

エンドポイントはFlaskで処理を識別する名前。テンプレートはHTMLの表示用ファイル名であり、ここでは名前だけを決める。

| 画面 | 目的 | ログイン | 表示URL | メソッド | エンドポイント | テンプレート |
|---|---|---|---|---|---|---|
| 写真一覧 | 平泉の写真と言葉を見る | 不要 | `/`、`/?page=2` | GET | `index` | `index.html` |
| ユーザー登録 | アカウントを作る | 不要 | `/register` | GET | `register_form` | `register.html` |
| ログイン | 自分のアカウントで利用する | 不要 | `/login` | GET | `login_form` | `login.html` |
| 写真投稿 | 写真と言葉を選び、投稿または下書き保存する | 必要 | `/posts/new` | GET | `post_new` | `post_form.html` |
| 投稿編集 | 自分の公開済み投稿を修正する | 必要・本人のみ | `/posts/<int:post_id>/edit` | GET | `post_edit` | `post_edit.html` |

下書き再開は `GET /draft`（`draft_resume`）で同じ `post_form.html` を使う。URLは別でも画面構成は投稿画面と共通。保存・削除などのPOST処理は `routes.md` に記載する。

## 3. 写真一覧（主画面）

### 部品の順序

1. アプリ名「平泉の細道 〜一枚の写真から、千年のことばを〜」。
2. 説明「平泉の景色に、心に残るひとことを」。
3. 未ログイン時は登録・ログインのリンク。ログイン時はユーザー名・ログアウトボタン。
4. 「写真を投稿する」。本人の下書きがあれば「下書きを再開」も表示。
5. 操作結果のメッセージ。
6. 写真を1列で表示。各投稿は写真、場所・投稿者、言葉と小さな出典リンク、読み方、投稿者のひとことの順。
7. 自分の投稿にだけ「編集」「削除」。削除には確認を挟む。
8. 「前へ」「次へ」とページ番号。存在しない移動先のボタンは出さない。

### 正常時

- 公開済み投稿だけを公開日時の新しい順に10件表示する。同時刻はIDの降順。
- 投稿がないときは「まだ投稿がありません」。下書きは公開件数にも含めない。
- 投稿・編集・削除後は一覧へ戻り、結果を表示する。
- 下書きを公開したときは公開日時を設定し、新しい投稿として先頭に表示する。
- 未ログインで「写真を投稿する」を押した場合は、戻り先に投稿画面を保持してユーザー登録画面へ移動する。

### エラー時

- ページ番号が整数でない、または1未満なら400。存在するページを超える場合は404。投稿ゼロの1ページ目は200で空一覧。
- 画像が取得できない場合は代替表示を出し、言葉やひとことは読める状態にする。
- 削除失敗時は投稿を残す。本人でない投稿への操作は404として扱う。

## 4. ユーザー登録

### 部品の順序

1. 見出し「ユーザー登録」。
2. ユーザー名入力欄。
3. パスワード入力欄。
4. 「登録する」。
5. 「登録済みの方はログイン」、写真一覧へ戻るリンク。

### 正常時・遷移

`POST /register` → 登録成功 → ログイン画面へ移動し「登録しました」。登録時には自動ログインしない。
投稿から来た場合の戻り先は、登録画面を経由しても引き継ぐ。既にログイン済みなら一覧へ移動する。

### エラー時

未入力・形式不正・ユーザー名重複は項目の近くに表示する（422）。ユーザー名は残し、パスワードは再入力してもらう。

## 5. ログイン

### 部品の順序

1. 見出し「ログイン」。
2. ユーザー名、パスワード。
3. 「ログインする」。
4. ユーザー登録へのリンク、写真一覧へ戻るリンク。

### 正常時・遷移

- 投稿から来た場合は成功後 `/posts/new` へ、下書き再開から来た場合は `/draft` へ戻る。
- 通常のログインは一覧へ戻る。
- 戻り先はアプリ内の許可した表示URLだけ。外部URLやPOST専用URLへ転送しない。
- ログアウトはPOSTで行い、一覧へ戻る。

### エラー時

認証失敗は「ユーザー名またはパスワードが違います」（401）。ユーザー名を保持し、パスワードを空にする。

## 6. 写真投稿・下書き再開

### 部品の順序

1. 見出し「平泉の一枚を投稿」。
2. 下書きがある場合は「下書きを再開」。保存済み下書きがある間は別の新規投稿フォームを出さず、再開を案内する。
3. 写真選択、選んだ写真のプレビュー。
4. 撮影場所「中尊寺／毛越寺／その他」と「写真の位置をYahoo!マップで表示しますか？」。
5. 「ことばを引く」。
6. 候補2件。各候補に言葉・読み方・解説・出典リンク・選択ボタン。
7. 「もう一度引く」。
8. 「写真に添えるひとこと」の入力欄、300文字以内の案内、「文章案に戻す」。
9. 「下書き保存」「投稿する」。
10. 「一覧に戻る」。

### 抽選と文章編集

- 初回は70種類から異なる2件を抽選。引き直しでは直前の2件を除く。
- 抽選はPOSTで候補欄だけを更新し、写真・場所・ひとことを保持する。
- 引き直し成功時は選択を解除するが、編集済み文章は保持する。通信失敗時は候補も選択も変更しない。
- 初回選択で文章案を入力する。編集済み文章がある場合は「新しい文章案に置き換えますか？」で確認し、断った場合は言葉だけ変更して文章を保持する。
- 「文章案に戻す」も確認してから置き換える。
- 言葉・読み方・出典は変更不可。文章案は元の言葉データを書き換えず、投稿ごとに編集する。

### 下書き保存・再開

- 画面には「下書きは自分だけが見られます。『下書きを保存する』を押すと保存され、『投稿する』を押すまで公開されません。一覧に戻っても、あとから下書きを再開できます。」と表示し、保存・公開・再開を案内する。幅600px以下では、この説明だけを`.85rem`で表示する。
- 自動保存はしない。「下書き保存」で写真・場所・選択した言葉・ひとこと・現在の候補2件を保存する。
- 未入力でも保存可能。ただし、入力済みの画像形式・容量、文字数、言葉ID等は検証する。
- 写真未選択も許可する。再開後に新しい写真を選ばなければ保存済み写真を保持する。
- 1人1件。既存下書きは同じレコードを更新し、別の下書きを増やさない。
- 再開時は保存済み写真をプレビューとして表示する。ファイル入力欄自体を復元するのではない。
- 候補・選択も再開でき、直前候補を避けて引き直せる。
- 下書き保存成功で「下書きを保存しました」。そのまま編集を続けられる。
- 公開時は同じ下書きを公開済みに変更し、下書き枠を空ける。二重投稿を避ける。
- 下書き専用一覧・自動保存・複数件保存・専用削除機能は初版に追加しない。

### 投稿成功・エラー時

- 公開には写真・場所・候補から選んだ言葉1件・空白以外のひとことが必要。
- 投稿成功で一覧の1ページ目へ移動し「投稿しました」。
- 未入力や文字数超過は422、不正な画像は422、容量超過は413。入力画面に留まって原因を表示する。
- 保存・投稿は画面を再読み込みしない送信を基本とし、エラー時は選択した写真と入力値を保持する。
- 保存失敗では既存下書きを壊さず「保存できませんでした」。未保存状態を維持し再試行できる。
- ログイン期限切れは401。自動で画面を離れず、再ログインを案内する。未保存の写真はページを閉じると失われる場合があることを伝える。

## 7. 公開済み投稿の編集

### 部品の順序

1. 見出し「投稿を編集」。
2. 現在の写真、差し替える写真の選択とプレビュー。
3. 撮影場所とYahoo!マップリンクの表示選択。
4. 現在の言葉・読み方・出典と、2件ずつ引き直して選び直す操作。
5. ひとことの編集欄。
6. 「変更を保存」、一覧へ戻るリンク。

### 正常時・エラー時

- 本人の公開済み投稿のみ表示する。下書きはこの画面で編集しない。
- 新しい画像を選ばなければ現在の画像を保持する。
- 保存成功は一覧へ。不正な入力は422でその場に留まり、既存投稿は変更しない。
- 存在しない投稿・他人の投稿・下書きのIDは404。
- 公開済み投稿の編集中データを下書きにはしない。未保存で離れるときは確認する。

## 8. 共通の確認と画面遷移

### 出典リンク

「外部の解説ページを別のタブで開きますか？」を表示する。「開く」で確認済みのURLを別タブへ、「キャンセル」でそのまま。確認後の「開く」を利用者が押す方式にして、別タブを開く操作を明確にする。アプリの入力内容は維持する。

### 未保存で離れるとき

- 写真・場所・抽選候補・選択・ひとことに未保存の変更があれば「保存していない変更があります。移動しますか？」。
- キャンセルで入力を続ける。移動を選ぶと未保存分だけ破棄され、保存済み下書きは残る。
- 保存直後や投稿成功後には離脱確認を出さない。
- ブラウザの閉じる・再読み込みにはブラウザ標準の確認を使う。文言は指定できず、端末によって表示されない場合もあるため、保存完了の表示を明確にする。

### 主な遷移

| 操作 | 移動先・結果 |
|---|---|
| 一覧 → 投稿（未ログイン） | ログイン → 投稿画面。下書きがあれば再開案内。 |
| 一覧 → 投稿（ログイン済み） | 投稿画面。 |
| 一覧／投稿画面 → 下書きを再開 | 同じ投稿テンプレートに保存済み内容を表示。 |
| 投稿画面 → 抽選／引き直し／下書き保存 | 同じ画面で結果を表示。 |
| 投稿画面 → 投稿成功 | 一覧1ページ目。 |
| 一覧 → 編集 → 保存 | 編集画面 → 一覧1ページ目。 |
| 一覧 → 削除確認 → 削除 | POSTで削除 → 一覧1ページ目。 |
| 出典 → 確認 → 開く | 外部ページを別タブで表示。元画面はそのまま。 |

共通エラー表示は `error.html` を使用する。これは業務画面を追加するものではない。表示URLと処理URLの詳細は `routes.md` を参照。


## 下書き削除（2026-10-13追加）

保存済み下書きのフォームに「下書きを削除する」を表示する。新規画面では初回保存の成功後に表示する。確認をキャンセルすると変更しない。

- URL：`/draft/delete`、HTTPメソッド：POST、エンドポイント：`draft_delete`、応答：JSON。テンプレートは既存の`post_form.html`。
- ログイン・CSRF・所有者・下書き状態を確認し、ID・送信識別子・版番号を照合する。公開投稿と他人の下書きは404、古い版は409、入力不正は422、DB失敗は500。GETは405。
- 成功時は下書きをDBから削除し、コミット後に写真を削除して、新規投稿画面へ移動する。未保存離脱確認を解除する。
- 写真削除失敗時は削除成功のみを表示せず、管理者への確認案内を表示し、回収する画像キーをサーバーログに記録する。DB行削除後の画像は配信されない。
- エラー時は入力を保持する。DB構造変更は不要。

## 公開後の言葉の選び直し（2026-10-14）

編集画面の「ことばを引き直す」で候補2件を表示する。新規投稿と共通の抽選履歴を使用し、抽選時に履歴を進める。候補を選び「変更を反映する」で公開中の言葉を更新する。「今のことばを使う」を選ぶと現在の言葉を維持する。引き直すと選択はいったん「今のことばを使う」に戻る。ひとことは維持し、「選んだことばの文章案を使う」を押して確認したときだけ置き換える。公開日時は維持する。保存せず離れる場合は未保存の確認を表示する。
