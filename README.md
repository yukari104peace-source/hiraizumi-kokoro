# 平泉の細道 〜一枚の写真から、千年のことばを〜

Python 3.13、Flask、Peeweeで作る写真共有アプリです。

## 現在の段階

写真投稿の最初の流れまで実装しました。写真一覧、ユーザー登録・ログイン・ログアウト、サーバー側セッション、CSRF対策、DBの6モデル、画像検証、CSV取り込みコマンド、自動テストが動きます。

写真と撮影場所を選び、2件の言葉を引いて1件選び、文章案を編集して投稿できます。利用者ごとに全件を一巡するまで重複せず、投稿・ログアウト・再起動後も続きから引けます。一巡後は再びランダムに選びます。下書きは1人1件、未入力でも手動保存でき、投稿開始画面から再開できます。保存した写真は本人だけが閲覧できます。別タブとの競合時は上書きせず案内します。公開済み投稿は、本人の一覧に表示される削除ボタンから、確認後に写真とともに削除できます。公開済み投稿は本人だけが写真・撮影場所・ひとことを編集できます。写真未選択なら現在の写真を維持し、公開日時は変更しません。言葉は編集画面で2件ずつ引き直して選び直せます。ひとことは自動で変えず、必要な場合だけ選んだ言葉の文章案に置き換えられます。別タブの更新と競合した場合は上書きを止めます。設計資料の全機能が完成した状態ではありません。

## 別の環境で再現する場合

仮想環境を作って有効にした後に実行します。

```bash
python -m pip install -r requirements-dev.txt
cp .env.example .env
```

`.env` のSECRET_KEYを自分のランダムな秘密鍵に置き換えてください。Python標準のsecretsで生成できます。見本の値のままでは起動しません。秘密鍵はチャットやGitに載せないでください。

```bash
python -m flask --app app:create_app init-db
python -m flask --app app:create_app run --port 5001
```

`init-db` はテーブルを準備するもので、既存テーブルの構造変更・マイグレーションには使えません。

## パッケージ

- 実行用は `requirements.txt`、テスト用は `requirements-dev.txt` に動作確認済みバージョンを固定しています。
- Flask-Login：ログイン管理。パスワードはWerkzeugでハッシュ化。
- Flask-Session＋CacheLib：単一サーバー向けのファイル保存セッション。12時間で期限切れ。
- Flask-WTF＋WTForms：入力検証・全POSTのCSRF対策。
- Pillow：JPEG／PNGの形式と実データ・容量・画素数を確認し、保存用に再エンコード。写真は5MiB、2,000万画素まで。
- python-dotenv：開発用 `.env` 読み込み。公開先では環境変数を設定。
- pytest：実データとは別の一時DB・画像・セッション保存先でテスト。
- email-validatorはメール登録を追加する場合のみ、openpyxlはxlsx直接読み込みに変更する場合のみ検討します。現在は入れていません。
- 依存関係確認：`python -m pip check`。

## 構成

- `app.py`：アプリ生成と各機能の接続。
- `config.py`・`extensions.py`：環境変数と認証・CSRF・セッション設定。
- `models.py`：User・Word・Post・WordDrawState・Like・Comment、外部キー・CHECK・下書き1件の制約。
- `forms.py`・`routes.py`：入力検証と実装済みのURL処理。
- `services/images.py`：画像の検証・保存。
- `services/words.py`・`commands.py`：CSV検証・差分確認・DB反映。
- `templates/`・`static/`：画面と公開するCSS・JavaScript。
- `instance/`：DB・写真・セッション。非公開、Git対象外。
- `data/words.csv`：更新版Excelの80行から重複をまとめた70種類を収録。確認先はdocs/word_sources.mdにも記録。
- `tests/`：自動テスト。
- `docs/`：要件・画面・ルート・DB設計。

`services/posts.py` は画像保存と投稿処理を担当します。保存失敗時は画像を片づけ、同じ送信を再試行しても二重投稿しません。

## 言葉のCSV取り込み

ExcelからUTF-8のCSVを書き出し、`data/words.csv` と同じ英語の列名に対応づけます。固定番号はword_code、抽選対象はis_active（1=対象、0=停止）。読み方・解説・出典名・確認先URL等は必須です。元のExcelを直接変更する機能はありません。

まず確認だけ行います。DBは変わりません。

```bash
python -m flask --app app:create_app import-words data/words.csv
```

差分を読んで反映するときだけ、次を実行し、確認に答えます。

```bash
python -m flask --app app:create_app import-words data/words.csv --apply
```

同じ固定番号は更新、新番号は追加。CSVから消えた番号は削除しません。投稿者のひとことは変更しません。実行前にDBのバックアップを取ってください。

## 自動テスト


認証・セッション無効化・CSRF・画像偽装・サイズ制限・DB制約・非公開画像へのアクセス・CSV取り込みの一括検証を確認します。CSRFを無効化せずにテストしています。

## 設定と公開前に残ること

`.env` と `instance/` はGitに含めません。`.env.example` だけ共有します。SESSION_DIRとUPLOAD_DIRとDATABASE_PATHで保存先を変更できます。秘密鍵を変更すると利用者の再ログインが必要になる場合があります。

開発サーバーをそのまま一般公開しないでください。無料の永続保存先・本番用サーバー・HTTPSは、全機能の動作確認後に選定します。公開時はAPP_ENV=productionにしてSecure Cookieを使います。CacheLibのファイルセッションは信頼できるサーバー専用の保存先を使い、複数サーバーで公開する場合は共有セッション保存方式を改めて選びます。

ログイン後の戻り先は一覧と新規投稿画面だけ許可します。アクセス数制限、管理者による削除運用、バックアップ手順なども公開前の確認事項です。

既存環境ではDBをバックアップ後、`python -m flask --app app:create_app init-db` で `word_draw_states` テーブルを追加し、30件のCSVを取り込みます。今回の作業環境には反映済みです。既存の3テーブルは変更しません。

履歴は利用者ごとにDBへ保存します。過去の抽選は記録がないため遡って登録せず、導入後から開始します。抽選成功で候補に出た2件を記録し、選んだ1件だけを記録する方式ではありません。画面の再表示や下書き再開では進みません。通信断で応答が届かなくてもサーバーで確定した抽選は記録に残ります。

奇数件の場合、最後の1件を出してから次の巡の1件を組み合わせます。同じ組の重複と直前の組は避けます。追加した言葉も対象となり、停止した言葉は新規抽選から除きます。対象が4件未満なら履歴を進めずエラーを表示します。

## いいね機能

写真一覧の投稿下部に「♡ いいね」と件数を表示します。ログインすると自分の投稿も含め、公開投稿に1人1回いいねでき、取り消せます。未ログインでは件数を表示し、ボタンからログインへ進みます。記録はDBに保存され、投稿を削除すると関連するいいねも削除されます。通知やいいねした人の一覧はありません。

既存環境への導入時は、DBをバックアップしてから以下を実行し、アプリを再起動してください。既存投稿は変更せず、`likes` テーブルと索引を追加します。

```bash
python -m flask --app app:create_app init-db
```

追加・取消はCSRF保護付きの `POST /posts/<post_id>/like` で行います。`action=like` または `action=unlike` を明示し、同じ操作の再送で件数が増減しないようにしています。

## コメント・返信

投稿下部の「コメント・返信」を開くと、コメントと1段の返信を読めます。ログインすると1〜200文字で投稿でき、自分のコメントを削除できます。削除時は本文を消し、「削除済み」の表示と既存の返信を残します。削除済みコメントへの新しい返信、返信への返信はできません。投稿を削除すると関連するコメント・返信も削除します。HTMLは文字として表示します。コメントの編集・通知は未実装です。

既存環境ではDBをバックアップし、`python -m flask --app app:create_app init-db` でcommentsテーブルを追加してからアプリを再起動します。

サーバー管理者は `python -m flask --app app:create_app remove-comment コメントID` で、不適切なコメントの本文を確認付きで削除できます。コメントIDは画面のHTMLの `id="comment-番号"` で確認できます。Web上に管理者権限は追加していません。

追加は `POST /posts/<post_id>/comments`（body、任意のparent_id）、本人削除は `POST /comments/<comment_id>/delete`。どちらもログインとCSRFトークンが必要です。同じ文章の投稿は禁止しません。

## Yahoo!マップリンク

投稿者は投稿・編集画面で「写真の位置をYahoo!マップで表示しますか？」を選べます。新規投稿は「表示しない」が初期値です。表示する場合、中尊寺・毛越寺は施設名と平泉町、その他は入力された具体的な場所名をYahoo!マップで検索するリンクを写真右下に表示します。

既存DBへ導入するときは、次のコマンドを実行してからアプリを再起動します。コマンドはDBを `instance/backups/` にバックアップし、列が追加済みなら何も変更しません。既存の公開投稿は地図表示を有効にし、既存の下書きは無効のままにします。

```bash
python -m flask --app app:create_app migrate-map-links
```
